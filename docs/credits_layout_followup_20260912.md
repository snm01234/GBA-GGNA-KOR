# 엔딩 크레딧 타일 충돌·배치 후속 수정

2026-09-12 갱신된 ss1·ss2·ss3·ss5·ss6·ss7·ss8을 기준으로 수정했다. 이전 수정은 목록 종료와 인명 한글화에 한정되어, 엔딩 스크립트의 고정 타일 할당과 좌표 문제를 놓쳤다.

## 원인

엔딩 스크립트 `0x00FAD8DF`부터 `0x00FAE11B`의 출력 명령들은 다음 값을 고정한다.

1. `08 <tile> 17 EC`: 다음 문장이 사용할 첫 글자 타일
2. `08 <index> 08 <color> 08 <y> 08 <x> 17 E1`: 목록 번호와 좌표

타일 시작값과 X좌표는 일본어 길이에 맞춰져 있었다. 한글 이름이 길어지면 다음 직함이 이전 이름의 마지막 타일을 덮어, 이름 아래에 직함 일부가 나타난다. X좌표를 그대로 쓰면 오른쪽 끝을 넘어 타일맵 반대쪽으로 감기는 현상도 발생한다.

ss3의 협력 명단은 배경용 빈 타일 영역까지 덮었다. `0x0600A400`의 64바이트는 BG0의 4bpp 빈 타일과 BG2의 8bpp 빈 타일이 공유한다. 여기를 글자로 덮으면 전체 배경에 색 무늬가 반복된다.

## 적용

- 크레딧 27개 화면, 출력 명령 75개를 모두 검사했고, 그중 73개 명령의 좌표 또는 타일 시작값을 변경했다.
- 기존 각 항목의 중심을 기준으로 한글 길이에 맞춰 X좌표를 다시 계산했다. 두 열 화면도 각각의 중심을 유지하며, 인접한 글자가 8픽셀 타일 경계를 공유하지 않게 했다.
- 실제 ARM 출력 함수가 소비한 타일 수를 읽어 다음 항목의 타일 시작값을 정했다.
- 협력 명단은 인명을 유지하고 이름 내부 공백만 줄였다. 모든 화면의 최대 타일 끝은 `0x0508`이며, 빈 배경 타일이 시작하는 `0x0520`보다 작다.
- 최종 ROM은 직전 ROM 대비 279바이트만 변경했다. 렌더러·그림 자산·게임 진행 데이터는 변경하지 않았다.

## 검증

- 캡처한 7개 상태의 실제 스크립트 좌표와 타일 시작값으로 ARM 코드를 실행했다. 수정 전 BG0 타일맵과 글자 VRAM이 저장된 상태와 바이트 단위로 일치함을 확인했다. 따라서 화면 깨짐을 실제 배치 조건에서 재현했다.
- 수정 후 27개 화면 전체에서 글자·타일 사각형의 중첩, 화면 밖 출력, 글자 타일 중복 할당, 빈 배경 타일 침범이 없음을 검사했다.
- [7개 상태 비교 이미지](../outputs/20260912_credits_followup/seven_states_before_after.png): 위에서부터 ss1, ss2, ss3, ss5, ss6, ss7, ss8. 왼쪽 수정 전, 오른쪽 수정 후.
- 비교 이미지는 실제 ROM의 출력 코드를 Unicorn으로 실행하고 캡처된 그래픽 메모리와 합성한 결과다. 전체 mGBA 재생 검증은 아니다. ss3 수정 후 진단에서는 이미 손상돼 저장된 공용 빈 타일 64바이트를 원래의 0으로 복원했다. 수정 ROM으로 정상적으로 장면에 진입하면 할당기가 이 영역에 도달하지 않는다.
- 원본 savestate와 배터리 세이브는 수정하지 않았다. 기존 상태에 남은 손상된 VRAM은 ROM을 교체해도 즉시 바뀌지 않으므로, ROM을 다시 열고 엔딩 시작 전 세이브에서 재생하여 확인해야 한다.
