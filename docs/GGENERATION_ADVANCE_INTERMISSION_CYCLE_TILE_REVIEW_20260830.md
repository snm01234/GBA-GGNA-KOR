# G Generation Advance 인터미션 순환 타일 한글화 검토

- 분석일: 2026-08-30
- 대상: 현재 승인 Main TIP과 사용자가 제공한 `ss1`, `ss2`, `ss3`
- 분석 성격: 읽기 전용. ROM 수정 없음
- 결론: **한글화 가능성이 높으며 원본 ROM 범위까지 확정됨**

## 1. 상태 대응

| 상태 | 중앙 포커스 | 위 비포커스 | 왼쪽 비포커스 |
|---|---|---|---|
| `ss1` | `作戦` | `編成` | `開発` |
| `ss2` | `編成` | `開発` | `作戦` |
| `ss3` | `開発` | `作戦` | `編成` |

세 상태의 내장 ROM CRC는 모두 현재 Main TIP의 `0xDAFADC01`과 일치한다. 따라서 오래된 ROM에 종속된 상태를 잘못 분석한 경우가 아니다.

사용자 설명 첫 문장의 `보급`은 화면 원문 `編成` 및 뒤의 `state2는 편성에 focus`와 다르다. 실제 구현 시 한글 표기는 우선 `작전 / 편성 / 개발`로 해석하는 것이 자연스럽다. `보급`이 의도된 최종 명칭이면 구현 전에 표기만 확정하면 된다.

## 2. BG가 아닌 OBJ 그래픽

왼쪽 원형 메뉴 전체는 BG 타일맵이 아니라 OBJ VRAM에 조립된다. 상태에서 분리 렌더링한 결과 일본어 글자와 원형 버튼이 OBJ 레이어에 완전히 나타나며, BG2/BG3에는 외곽 프레임과 배경만 있다.

### 2.1 포커스 슬롯

- 원형 본체: OAM 13, 화면 `(31,27)`, `64x64`, OBJ 타일 `0x000–0x03F`, 팔레트 뱅크 0
- 강조 오버레이: OAM 0–4, OBJ 타일 `0x08C–0x0CD`
- 강조 오버레이 팔레트: `ss1=4`, `ss2=5`, `ss3=2`
- 중앙 위치와 OAM 구조는 고정이며 선택 항목에 따라 원형 본체의 글자 타일이 다시 적재된다.

포커스 본체에서 항목별로 실제 교체되는 OBJ 타일 위치는 정확히 18개다.

`0x019–0x01E`, `0x021–0x026`, `0x029–0x02E`

### 2.2 비포커스 슬롯

- 슬롯 A: OAM 14–17, OBJ 타일 `0x040–0x063`, 조립 크기 `48x48`
- 슬롯 B: OAM 18–21, OBJ 타일 `0x064–0x087`, 조립 크기 `48x48`
- 두 슬롯은 위와 왼쪽 위치를 선택 상태에 맞춰 교대한다.
- 비포커스 팔레트 뱅크는 세 상태 모두 1이다.

항목별 교체 위치는 다음과 같다.

- `編成 → 開発`: 9타일 — `0x049, 0x04A, 0x04B, 0x04D, 0x04E, 0x04F, 0x054, 0x056, 0x05B`
- `編成 → 作戦`: 11타일 — `0x06D, 0x06E, 0x06F, 0x071, 0x072, 0x073, 0x078, 0x07A, 0x07D, 0x07E, 0x07F`
- `ss2`와 `ss3`의 비포커스 `作戦` 바이트는 서로 완전히 같다.

## 3. ROM 소스 확정

런타임 오브젝트 관리자에서 이 메뉴의 활성 패키지 포인터는 `0x08C493B4`로 확인된다.

| 항목 | 값 |
|---|---:|
| 패키지 파일 오프셋 | `0x00C493B4` |
| 패키지 포인터를 사용하는 코드 위치 | `0x00064980` |
| 원시 4bpp 아틀라스 시작 | `0x00C4FC98` |
| 원시 4bpp 아틀라스 끝(포함) | `0x00C51177` |
| 크기 | `0x14E0` / 5,344바이트 |
| 타일 수 | 167 (`0x000–0x0A6`) |
| 팔레트 데이터 시작 | `0x00C51178` |

아틀라스는 압축 스트림이 아니라 ROM에 그대로 저장된 4bpp 타일이다. 각 상태의 대상 OBJ 타일은 이 범위의 타일과 바이트 단위로 일치한다.

## 4. 아틀라스의 공유 구조

완전한 포커스/비포커스 그림 6장을 독립 저장한 구조가 아니다. 기본 그림과 항목별 교체 타일을 조합한다.

| 아틀라스 타일 | 역할 |
|---|---|
| `0x000–0x03B` | 포커스 `作戦` 기본 원형(빈 타일 반복으로 64개 OBJ 셀 구성) |
| `0x03C–0x05B` | 비포커스 `編成` 기본 원형 |
| `0x05C–0x064` | 비포커스 `開発` 교체 9타일 |
| `0x065–0x06F` | 비포커스 `作戦` 교체 11타일 |
| `0x070–0x081` | 포커스 `編成` 교체 18타일 |
| `0x082–0x093` | 포커스 `開発` 교체 18타일 |
| `0x094–0x0A6` | 공통 포커스 강조 오버레이 |

이 구조 때문에 기본 `作戦`/`編成`만 고치거나 현재 화면의 VRAM 타일만 고치면 다른 포커스 상태에서 일본어가 다시 나타난다. 기본과 네 교체 집합을 함께 재구성해야 한다.

## 5. 한글화 가능성

판정은 **높음**이다.

1. 실제 소비 리소스와 ROM 원본 범위가 확정되었다.
2. 데이터가 무압축 4bpp이므로 재압축 크기나 포인터 재배치 위험이 없다.
3. `작전`, `편성`, `개발`은 모두 원문처럼 두 글자라 기존 64x64/48x48 캔버스에 배치 가능하다.
4. 원형 배경, 팔레트, 강조 오버레이를 보존하고 글자·외곽선 픽셀만 다시 그릴 수 있다.

다만 공유 베이스 방식이므로 단순한 타일 덮어쓰기보다 다음 방식이 안전하다.

1. 세 상태에서 포커스 `64x64`, 비포커스 `48x48` 캔버스를 각각 복원한다.
2. 원문 글자와 그림자 영역을 항목별 배경 픽셀로 복구한다.
3. 동일한 노란 면/짙은 외곽선 스타일로 한글 두 글자를 그린다.
4. 기본 아틀라스와 항목별 교체 타일 집합에 다시 분해한다.
5. 공통 강조 오버레이 `0x094–0x0A6`과 팔레트는 바이트 단위로 보존한다.

한국어 글자가 기존 교체 타일 영역 밖으로 나가면 공유 베이스의 다른 항목을 오염시킬 수 있다. 따라서 글자 폭과 외곽선을 기존 18타일(포커스), 9/11타일(비포커스) 교체 영역 안에 맞추는 검증 게이트가 필요하다. 현재 두 글자 구성이라 충분히 맞출 수 있을 것으로 판단한다.

## 6. 구현 시 검증 항목

- ROM 변경이 `0x00C4FC98–0x00C51177`의 승인된 글자 타일에만 제한되는지 확인
- 팔레트와 `0x094–0x0A6` 강조 오버레이가 그대로인지 확인
- `작전 → 편성 → 개발 → 작전` 양방향 순환에서 중앙·위·왼쪽의 세 글자가 모두 맞는지 확인
- 각 항목의 포커스/비포커스 형태를 모두 확인
- 화면 전환 후 새 상태를 캡처해 OBJ VRAM이 패치 ROM에서 다시 적재되었는지 확인
- 기존 `ss1–ss3`는 ROM 패치 후 복원하면 저장 당시 VRAM을 되살리므로 최종 시각 검증용으로 재사용하지 않음
